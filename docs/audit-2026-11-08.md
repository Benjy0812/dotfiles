# Repo audit, 2026-11-08

**What this repo does:** These are personal Linux desktop configs, organised as one profile per OS. `dotfiles.bash` (2,367 lines of bash) compares the active profile with `~/.config` and copies changes either way, keeping backups and an undo log. There is also an Omarchy/Hyprland plugin, `benjy.solo-workspaces`, a NixOS flake, and local patches in `fixes/`.

**Load assumed:** one person on one machine, plus one long-running `watch` process started at login.

Both test suites pass (22 bash, 10 Lua). Findings 1 and 2 were reproduced in a scratch copy; finding 3 was checked against Omarchy's source.

## Must fix

### 1. Solo-workspaces does nothing on your second monitor, and that includes the games workspace

`solo-workspaces.lua:81-93`, `custom.lua:159`

- **What this is:** The plugin turns a workspace number into a "slot" (1-10), then decides whether to move a window.
- **Problem:** Omarchy now numbers each monitor's workspaces itself. DP-3 gets 11-20 (see `~/.local/state/omarchy/monitor-workspaces`). The plugin looks for a global `monitor_workspaces`, but Omarchy's module never sets one, so the plugin only knows ids 1-10. On DP-3 `slot_on` returns nil and `place()` stops early. Games sent to workspace 11 are never kept alone, and other windows opened there are not moved off.
- **Fix:** In `workspace_for`, use Omarchy's module: `local ok, mw = pcall(require, "default.hypr.monitor-workspaces")`, then call `mw.workspace_id(monitor, slot)`. `require` hands back the copy Omarchy already loaded, so nothing runs twice.
- **If we skip it:** The plugin only works on the 144Hz monitor. The comment in `custom.lua` promises protection that never happens.

### 2. After an undo, the next sync reverses your edit

`dotfiles.bash:1042-1076`, `record_sync` at L409

- **What this is:** `synced.tsv` stores each file's content hash from the last sync. That is how the script tells "edited in ~/.config" from "repo is newer".
- **Problem:** Undo puts the files back but leaves the hashes from after the run. Reproduced in both directions:
  - Repo edit `c`, `push`, `undo`: status says "edited in ~/.config", and `pull` copies the old `a` over your repo edit.
  - Live edit `b`, `pull`, `undo`: status says "repo is newer", and `push` replaces `b` with `a`.
- **Fix:** Let `record_sync` take a second file to hash: `hash_of "${2:-$1}"`. In `undo_last`, call `record_sync "$dest"` after restoring a stash, and `record_sync "$dest" "$src"` after restoring a pulled repo file.
- **If we skip it:** The menu pre-ticks these as safe, so Enter reverts work. `watch --auto` is worse: undo's copy into `~/.config` triggers it, and it pulls the old file over the repo edit without asking.

### 3. Undo can reverse the wrong changes

`dotfiles.bash:1188-1189`, `L1854`

- **What this is:** Each push, pull or restore gets a run id, and undo reverses the newest run.
- **Problem:** Two places never start a new run.
  - `watch --auto` pulls every edit under the id from login time. After a `push`, the next auto-pull adds a line under that old id at the end of the history. `undo` then reverts every auto-pull since login and leaves the push alone.
  - Restore from the Backups menu writes into the previous Sync's run, so one undo reverses both.
- **Fix:** Call `new_run` before `pull_file` in `watch_config`. In `backup_restore_pick`, replace `N_COPY=0 N_BACKUP=0` with `new_run`.
- **If we skip it:** "Undo last sync" puts back things you did not mean to undo.

## Should fix

### 4. Nothing tests the state after an undo

`tests.bash:81-86`

- **What this is:** The undo test only checks the file's content.
- **Problem:** Finding 2 passes that test.
- **Fix:** After the undo, add `check "undo leaves the edit pending" has "edited in ~/.config" "$("$D" status)"`, plus the mirror case for push.
- **If we skip it:** Finding 2 can come back unnoticed.

### 5. `setup` rewrites `hyprland.lua` with `sed`, with no test

`dotfiles.bash:623-653`

- **What this is:** It adds a `dofile` line and a `require("hypr.autostart")` line to your live Hyprland config, then reloads Hyprland.
- **Problem:** It is meant to be safe to run twice, but nothing checks that. A duplicate or missing line breaks the desktop at the next login.
- **Fix:** One test: a temp `hyprland.lua` with a stub `hyprctl` first in PATH. Run `setup` twice and assert exactly one `custom.lua` line and one `require("hypr.autostart")`.
- **If we skip it:** A future edit to these `sed` lines breaks the desktop silently.

### 6. Leftover code for bar-widget plugins

`dotfiles.bash:556-558, 593-598, 605-608`, `OMARCHY_RESTART`

- **What this is:** Plugins with a `Widget.qml` hook into `bindings.lua` and get patched into `shell.json`.
- **Problem:** No plugin has a `Widget.qml` any more. The last one was monitor-workspaces, removed in `ecc82bf`. This is about 15 lines that no current plugin uses.
- **Fix:** Delete those branches and `OMARCHY_RESTART`. Always hook into `autostart.lua`.
- **If we skip it:** About 15 extra lines to read and keep working, for a case that does not exist.

### 7. Docs and comments describe a plugin that is gone

- **What this is:** These still point at the removed benjy.monitor-workspaces plugin:
  - `README.md:16-17`
  - `profiles/omarchy/README.md:9-10`
  - the solo README's "With monitor-workspaces" section
  - the comment at `custom.lua:150-152`
- **Problem:** The links are dead. `README.md` also links `omarchy/README.md` (should be `profiles/omarchy/README.md`). `config.default.lua` and `solo-workspaces.lua:17` say `setup` creates the settings file from it, but `dotfiles.bash` never copies it.
- **Fix:** Drop the dead links and correct the comments. After finding 1, the solo README section can say it follows Omarchy's own per-monitor numbering.
- **If we skip it:** Readers follow dead links, and the wrong comments helped hide finding 1.

### 8. Two copies of the same glob check

`dotfiles.bash:189-197`, `489-497`, `L1929`

- **What this is:** `matches_any` and `first_match` loop over globs the same way, and `menu_select` writes the loop a third time.
- **Fix:** `matches_any() { first_match "$@" >/dev/null; }`, and at L1929 `pattern=$(first_match "$path" "${USER_IGNORE[@]}")`.
- **If we skip it:** A change to the matching rule has to be made in three places.

## Nice to have

9. **`diff_stat` runs `diff` twice per file** (`L804-805`). One `diff "$1" "$2" | awk` can count `>` and `<` together. It is only noticeable in big Sync lists.
10. **Fish completions are missing commands.** In both `fish/completions/dotfiles.bash.fish` copies, the `cmds` list lacks `track add untrack layer`. The `apps/` copy also lacks `skipped edit rebuild`.
